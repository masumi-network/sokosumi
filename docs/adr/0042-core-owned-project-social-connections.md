# Core owns project social connections through Composio

Sokosumi Core owns Project authorization, scheduling authorization, connection lifecycle, and audit records for Social connections. Composio is the server-side broker for provider OAuth credentials and restricted X execution only, so neither the browser nor an automation actor can hold or authorize use of an external publishing credential.

Composio's Organization / Project is Composio tenancy (production versus staging), not a Sokosumi customer Project. Do not model a Sokosumi Project as the Composio `userId`: callback identity verification requires the connecting human to prove the same identity that began the flow. Use that human's stable Sokosumi user ID (`sokosumi:user:${userId}`) as the connector, create a SHARED connected account, grant only an opaque Core executor (`sokosumi:project-executor:${projectId}`), and store the resulting connected-account ID on the Sokosumi Project. Do not use `allowAllUsers`; Core remains the source of truth for membership and roles. Each environment uses a customer-owned X OAuth 2.0 app and a custom Composio Twitter auth config. Composio stores and refreshes tokens; Core authorizes every publish, schedule, disconnect, and status check. Scheduled posting is Core's job — Composio's X toolkit has no future-publish field.
