# Publish to every connected provider through one adapter seam

X-only publishing limited drafts, scheduling, and Soko Bot tools to one provider even though six could be connected. Core now maps each provider to an explicit adapter behind the existing lease/retry publisher: X, LinkedIn, Facebook, Instagram, TikTok, and YouTube share the session/execute/staging helpers in `apps/core/src/clients/social-post-providers/`, while their tool sequences, argument shapes, and result parsing stay explicit in one file per provider. A declarative engine was rejected because the platforms differ in sequencing (Instagram is two-step, TikTok queries privacy and polls status, LinkedIn registers assets, Facebook targets a Page), which would have turned configuration into a framework.

Provider rules are shared data in `@sokosumi/utils` (`SOCIAL_POST_TEXT_LIMITS`, `SOCIAL_POST_MEDIA_RULES`, requirement flags), so Core validation, the Web composer, and Soko Bot contracts cannot drift from each other. A post's provider comes from its active connection; a draft without one stays X until a connection is attached, and switching the connection re-derives the provider and re-validates stored text and media. There is no schema migration: `SocialPost.provider` was already a free string, and `ProjectSocialConnection.externalAccountId` already stored each provider's identity id.

Media reaches providers the cheapest way each tool allows: adapters whose tools accept public URLs hand over the Drive file URL, and file-only tools download bytes through the existing SSRF-guarded helper at the provider's byte caps before staging them through Composio. Once a create/publish call is initiated, a timeout is an unknown outcome rather than a retry, because the provider may already have published; this stays the rule for every provider: X, LinkedIn, Facebook, Instagram, TikTok, and YouTube. Facebook now binds a connection to the account's single managed Page, so existing Facebook connections must reconnect. TikTok's privacy level is chosen at publish time from the account's live options and recorded on the attempt, so unaudited apps publish privately instead of failing.
