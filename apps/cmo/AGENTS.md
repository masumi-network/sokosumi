# CMO app

CMO is the product at cmo.xyz (see **CMO** and **Sign in with Sokosumi** in [GLOSSARY.md](../../GLOSSARY.md), and [ADR 0045](../../docs/adr/0045-cmo-signs-in-through-core-oauth-provider.md)). This app is its own Next.js deployment at app.cmo.xyz, not part of Web.

- **Company.** CMO.XYZ belongs to Sumico, Inc., not utxo AG. Name Sumico, Inc. wherever the product names its company. "utxo AG" in eval cases, fixtures and Core is a customer and a workspace, not the owner; leave it.
- **Own components.** Build every component inside `apps/cmo`; Web's components stay Web's.
- **Nothing opens or names Sokosumi.** The owner works with Cuso in CMO, so a reply, receipt, card or link never leads into Sokosumi or names its features (Content Studio, Tasks, Files). Core strips links into Sokosumi from a Cuso reply (`withoutSokosumiLinks` in `@sokosumi/utils`, applied in `buildActionResponse`), and the chat applies it again when it renders (`renderInline`), which also covers older messages. What Cuso did on a request shows as his own message (`RequestNote`), flat and in his words. Guards: `action-response-cmo.test.ts` in Core runs every receipt on a Cuso turn, "renderInline" in `cmo.test.tsx`, and the persona test in `packages/soko-bot/src/__tests__/cmo.test.ts`. Sign in with Sokosumi is the one place the name belongs.
- **Actions for the client app are server action references.** Every function in the `actions` that `src/app/home.tsx` hands `<CmoApp>` or `<OnboardingFlow>` must be a `"use server"` export or its `.bind(null, …)`. An inline arrow (`() => requestStrategy(projectId)`, #7677) passes typecheck and every unit test, then breaks every signed-in page in production ("Functions cannot be passed directly to Client Components"). `src/app/client-actions-guard.test.ts` refuses it.
- **Written for non-marketers.** Everything an owner reads, in the app and from Cuso, is for a founder who is not a marketer: plain words, the brand, the buyer and the concrete action, one number per fact. Rules and the banned-word list are in [`DESIGN.md`](DESIGN.md) under Voice and tone.
- **Submit buttons.** Use `SubmitButton`; it shows the loading bar and keeps the pressed button focused.
- **Brand and design system.** Read [`DESIGN.md`](DESIGN.md) before copy work (product, voice, agent naming) and [`design-system.md`](design-system.md) before UI work (neobrutalism, the landing page's look: the five rules, colour, line, shadow and type tokens, components, how Cuso is used). Both are CMO's own, separate from Web's, and the CMO.XYZ-Style-Guide repository syncs from them. Take every colour, size, line width, radius and shadow from the tokens in the `:root` block of `src/app/globals.css`; `/design-system` (local and preview deploys only) renders them with the base classes, Cuso's poses and the onboarding parts in both themes, and `/design-system/onboarding/{hire,reading,writing,asking,brand,plan,planning,launch,launch-connected,subscribe,subscribe-confirming}` `/design-system/app/{chat,strategy,calendar,seo,results,brain,channels,settings}` and `/design-system/pages/{signed-in,invite-only,sign-in-problem,name-setup,error}` (`?theme=dark`) render each real screen over fixture data; any unknown path shows the 404. `src/components/phone-feeds.css` and `showcases.css` draw the networks' own UIs, so the visual guards skip them. `src/design-guards.test.ts` holds the locked rules: the token values the docs name, borders only as the 1px hairline or a line-width token, shadows only from the two hard shadow tokens (4px and 6px, and their Iris and strip colours) and no blur, a hard shadow only on something to act on (a button, link or input; never a card that is not a button), the same shadow on every tab, filter, pace or plan of a set with Iris filling the picked one, radii from tokens, type only in the scale's sizes, Iris, green and yellow as fills only, no gradients, colour literals only in the `:root` block of `globals.css`, the face only through `--font-sans`, no em dashes or hedges in copy, an `alt` on every image, and no removed focus outline.
- **Mascot.** The mascot is called Cuso; his drawings live in `public/cuso/` (see Cuso's poses below). The logos (`Logo` in `src/components/logo.tsx`) are approved lockups from the [Masumi Family Brand Guide](https://github.com/masumi-network/Masumi-Family-Brand-Guide) (`logos/cmo-xyz/lockups`), copied unchanged into `public/logo/`. A page whose hero shows a lockup hides the header's. Never recolour one, put it on another background or show it narrower than 120px; only `Logo` names the files (a design guard holds this). The guide's other lockups are approved on Iris, which no CMO page uses behind a logo yet. The app icons (`public/icon.svg`, `favicon.ico`, `apple-icon.png`, linked from `metadata.icons` in `src/app/layout.tsx`) are the guide's Iris monogram, approved on white and on black. They live in `public/` so their URLs stay stable for outside links. `favicon.ico` (16, 32, 48 px) is rasterised from `icon.svg`, so change the SVG first. `apple-icon.png` keeps a solid black tile because iOS fills transparency with black.
- **Signed out.** The marketing site is www.cmo.xyz (`masumi-network/cmo-website`); its "Try Cuso free" and "Log in" link to `/signup` and `/signin` here. A signed-out visit to `/` goes to `/login`, which goes on to `/signin`, so app.cmo.xyz always opens on sign in. `/signup` and `/signin` go straight to Sokosumi's Register and Log in; Web gives those pages CMO.xyz's look when CMO's callback is the redirect. Sign-in errors land on `/login`, which redirects to `/signin` when there is no error. Those Web pages name CMO.XYZ, not Sokosumi, in the tab title, the cookie notice and the imprint link, and Core's sign-in code email does the same for a code asked for inside CMO's OAuth request (`signsInToCmo`); the terms, privacy, acceptable-use and imprint links point to CMO.XYZ's own legal pages. Sign out leaves the `cmo-signed-out` cookie (`src/lib/signed-out.ts`): the Sokosumi session outlives CMO's, so the next sign-in sends `prompt=login` and Sokosumi shows its form, where the person can use another email; the proxy drops the cookie once someone is signed in.

Hiring saves each as a PNG under "Brand research/Logo" (`saveCmoBrandLogo`), the Brand step shows them, and a styled picture carries the full logo, its dark version on a dark corner (`logoForPicture`), falling back to the Project's icon. A Cuso with an approved plan and no page read yet (no file under `Full pages/`) is captured again, logo included, one Cuso per production sync and at most every six hours (`scheduleMissingCmoBrandIndex`); a capture that stops logs the step it stopped in (`cmo_brand_media`, `brandMedia.step`); the Project's icon (`project.logo`) stays the favicon, an avatar. Locally set `CHROMIUM_EXECUTABLE_PATH` in `apps/core/.env` to your Chrome. What research could not settle becomes yes/no `questions` on the Brand Brain, asked one at a time on the Research step while Cuso reads; a tap answers at once and moves on, and "Add more details" sends the owner's words with the next tap, whatever the answer ("Skip for now" keeps them in CMO's cookie as `questions`, and the Brand step lists what is left); a yes lands in its section as a confirmed finding (with the details), and a not sure lands only its details. A no lands as what is true instead ("Not true: …" without a note) and its question stays `corrected: false` until that section's answer is rewritten; the next strategy request tells Cuso to rewrite those sections with `save_brand_brain` before he plans (`brandBrainCorrections`). Core also keeps the no as a fix on its section (`answerCmoBrandQuestion`): once Cuso's current turn ends, a short fix turn rewrites that section and patches the plan, if there is one (`startNextCmoChange`). Cuso starts the first plan himself once the research turn ends (`startCmoPlanAfterResearch`), so the founder reads the Brand Brain while he writes. The Brand step shows the business's logo on the promise card, a "Your look" row with the DESIGN.md colours, fonts and file (`brandVisual`), and Cuso's market map (`reveal.map`) above the competitors. "Looks like us" approves the Brand Brain and asks for a plan only when none exists yet; Core hands back a plan already being written, and the Plan step shows its progress. An edit or a typed correction on the Brand step is a fix on its section too (`POST /v1/cmo/projects/{projectId}/brand/fix`).

The plan's yes/no questions sit on the Plan step as assumption chips; a no sends the plan back to Cuso (Update strategy), and "Write a new strategy" under Ask for a change asks for a fresh one without a note. Approving the plan opens Subscribe, the CMO plan checkout ([ADR 0068](../../docs/adr/0068-cmo-sells-its-plans-through-polar.md)): Core's step is `checkout` from approval until the Project has a CMO subscription that has not ended (or Tester credits), then `accounts` until a network is connected, then `done`. Under each reply, "How I got here" folds the steps and summaries Core keeps on the message (`metadata.reasoning`: a part with `kind: "step"` is a step, one without a kind a summary). Everyone who works with a Cuso sees his summary; a personal Soko Bot's stays with its owner. With no summary, only the steps show.
- **Two languages.** Cuso writes to the owner in the language of their latest chat message, and every piece in the strategy's `contentLanguage`, the audience's: a calendar entry's title, brief and story and the pillar names belong to the piece; the rest of the strategy explains it to the owner. Decline cancels it; `PATCH …/drafts/{postId}` changes its words. A turn files one report card per kind: reporting again rewrites the card (`reportCmoUpdate`). ## Run CMO locally against a local Core

Cuso needs Core's CMO routes and migration, so a branch that changes them runs against its own Core and database, never the shared dev Neon branch.

1. **Database.** Create an empty local Postgres database and point `apps/core/.env` and `packages/database/.env` at it. On Postgres 14/15, `prisma migrate deploy` fails on an old migration; create the schema from the Prisma files instead: `CREATE EXTENSION pg_trgm;`, then apply `pnpm exec prisma migrate diff --from-empty --to-schema prisma --script` (from `packages/database`) with `psql`. Seed test accounts with `CLOUD_AGENT_DB_FORCE=1 node scripts/agent-db/seed-auth-fixtures.mjs` (`alice@sokosumi.test` and the others, password `Password123!`).
2. **Core and Web.** Core's `.env` needs `SOKO_BOT_ENABLED="true"`, `SOKO_BOT_RUNTIME_ADAPTER="in-process"` and an `AI_GATEWAY_API_KEY`, with `BETTER_AUTH_URL` and `WEB_APP_BASE_URL` on your local ports. Web needs Node 26 (`.nvmrc`, `apps/web` `engines`) and `CORE_APP_BASE_URL` / `NEXT_PUBLIC_CORE_APP_BASE_URL` on that Core.
3. **CMO's OAuth client.** Signed in as a test account, `POST {core}/auth/oauth2/create-client` with `token_endpoint_auth_method: "client_secret_basic"`, `grant_types: ["authorization_code", "refresh_token"]` and `scope: "openid sokosumi:api offline_access"`. Better Auth only registers `https` redirect URIs on non-loopback hosts for web clients, so register a placeholder, then set the real callback on the row in your local database: `UPDATE "oauthClient" SET "skipConsent" = true, "redirectUris" = ARRAY['http://localhost:<cmo port>/api/auth/callback/sokosumi'] WHERE "clientId" = '<client_id>';` (authorize matches the URI exactly). Set Core's `CMO_OAUTH_CLIENT_ID` to this `client_id` and restart Core: every `/v1/cmo/**` write from another client, an API key or a session gets 403 `cmo_client_required`, and none is allowed while it is unset.
4. **CMO.** `apps/cmo/.env.local` holds `BETTER_AUTH_URL` (CMO's origin), a random `BETTER_AUTH_SECRET`, `CORE_APP_BASE_URL`, and the client's `SOKOSUMI_OAUTH_CLIENT_ID` / `SOKOSUMI_OAUTH_CLIENT_SECRET`. Start it with `PORT=<cmo port> pnpm dev`.

The in-process runtime has no sandbox, but it runs Cuso's read-only web tools (`web_search` through the AI Gateway, `web_fetch`) itself, so Cuso reads the real site locally too. Shell and workspace tools stay sandbox only.

To run a CMO rhythm now instead of waiting for its schedule, move its `nextRunAt` into the past (`soko_bot_schedule.systemKey` is `cmo-daily-run` or `cmo-weekly-review`; the column is UTC) and call `GET {core}/sync/soko-bot-schedules` with `Authorization: Bearer <CRON_SECRET>`.
