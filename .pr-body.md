## Summary

This PR adds support for grouped input schemas with tabbed navigation, allowing agents to organize their input fields into multiple groups/pages. Users can navigate between groups using tabs, with progressive unlocking of groups as they complete validation.

## Key Changes

### New Components
- `GroupedInputTabs`: Tabbed interface for navigating between input groups with smooth animations
- `MotionTabs`: Animated tabs component built with Motion (Framer Motion) for smooth transitions
- `MotionHighlight`: Highlight component for animating tab selection indicators

### New Hooks & Utilities
- `useGroupedInputWizard`: Custom hook managing grouped input navigation state, validation, and unlocking logic
- `input-schema.ts`: Helper utilities for parsing and flattening input envelopes (both grouped and flat schemas)

### Core Updates
- Updated `InputEnvelope` type to support both `InputDataEnvelope` and `InputGroupsEnvelope`
- Modified job input forms to handle both grouped and flat input schemas
- Updated API route handlers to flatten grouped schemas before processing
- Enhanced validation logic to support per-group validation

### Schema Changes
- Added `InputDataEnvelope` and `InputGroupsEnvelope` types to masumi package
- Updated `InputEnvelope` to be a union type supporting both formats

## Architecture Benefits

- **Backward Compatible**: Existing flat input schemas continue to work without changes
- **Progressive Disclosure**: Groups unlock sequentially, improving UX for complex forms
- **Type Safe**: Full TypeScript support with discriminated unions for envelope types
- **Smooth UX**: Animated transitions between groups using Motion library
- **Validation**: Per-group validation ensures users complete each step before proceeding

## Technical Details

- Uses Motion (Framer Motion) v12 for smooth animations
- Maintains internal flat data structure while supporting grouped presentation
- Wizard state manages active group, max unlocked group, and validation state
- Tab navigation respects unlocked groups (can't skip ahead)

## How to Test

### Workflow 1: Hire Agent
To test grouped inputs in the "Hire Agent" flow:

1. Use Proxyman (or similar proxy tool) to intercept the API response containing the agent input schema
2. Modify the response to include the `input_groups` structure (see sample JSON below)
3. The form should render with tabs for each group
4. Test navigation between groups, validation, and form submission

### Workflow 2: HITL Agent (Human-in-the-Loop)
To test grouped inputs when a job is awaiting input:

1. Create or find a job that is in "awaiting input" status
2. Update the database record for the `JobEvent` with the grouped schema structure
3. Set the `inputSchema` field to the JSON structure below
4. Refresh the job details page
5. The form should render with tabs, and you should be able to navigate through groups
